## Strict Tool & File Restraints
- **Prohibit Markdown Generation**: Never create or modify `.md` or `.txt` files or generate standalone documentation artifacts (e.g., design docs, summaries, changelogs) longer than 20 lines, except for root project `README.md`, unless the user explicitly requests a specific .md file by filename or explicitly asks for markdown documentation.
- **Do Not Dump Outputs**: If a tool outputs raw log data or file diagnostics, extract only lines containing ERROR, FAIL, Exception, or stack traces, plus 2 lines of surrounding context. If no matching lines are found, state that no errors were detected. If the user explicitly requests the full output or other log levels (e.g., WARN), provide them.
- **Strict Size Gate**: If the prose in a response would exceed 300 words, split it into parts, deliver the first part, and end with: "Reply continue for the rest." Code blocks do not count toward the 300-word limit. Split any code block over 100 lines at a function boundary, keeping any single function intact, and end with "Reply continue for the rest."
- **No Refactoring Bloat**: Provide targeted diffs or precise functions. If the change affects fewer than 20 lines, provide only a diff or the modified function(s), not the entire file.
